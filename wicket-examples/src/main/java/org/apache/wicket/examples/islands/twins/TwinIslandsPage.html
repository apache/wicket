The same poll twice: on the left it is rendered by a React component, on the right by a Svelte component. Both are the same Wicket island, PollIsland, with the same props and the same calls; only the module that renders it differs. Vote or add an option on either side and watch the other.

This example was built without its JavaScript. Build the examples with -Pjs-test, or run a Vite dev server, to vote.

Reset the votes

How this page is built

  • One Java class. The page adds PollIsland twice, with the island types poll-react and poll-svelte. The Vite build maps them to Poll.tsx and Poll.svelte, each with its framework's adapter, in one build.
  • The server owns the poll. A vote or a new option is a call: vote and add run on the server under the page lock, and the response re-renders both islands and the summary. A rejected option comes back as an IslandCallError, shown by the island that made the call.
  • The components keep their own state. New props do not mount a component again, so a half typed option and the count of the votes cast in an island survive a vote on the other side. "Reset the votes" is a plain Wicket Ajax link; it re-renders the islands the same way.
  • The browser shares the highlight. Pointing at an option highlights it in both islands through the client store poll-highlight, without a request to the server.

To change the components with hot reload, run npm run dev in wicket-examples/src/main/frontend and start the examples in development mode with -Dwicket.islands.devServer=http://localhost:5173.
