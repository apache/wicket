Find the hidden treasures. Each probe that misses tells you how far away the nearest hidden treasure is. The board is a React component, mounted as a Wicket island; everything around it is plain Wicket.

This example was built without its JavaScript. Build the examples with -Pjs-test, or run a Vite dev server, to play.

How this page is built

Four React components are mounted as islands. Each has a Java class that places it in the page, and a module under frontend/src/treasurehunt that renders it; the source viewer shows both.

  • The board (TreasureBoard) is an Island. Its props are a projection of the game without the treasure positions, so the browser never sees them. A click is a page-bound call: probe runs on the server under the page lock, changes the game and adds the status line and the history to the Ajax response.
  • The probe history (ProbeHistory) shares the hovered cell with the board through a client store. Hovering never reaches the server.
  • The name and colour field (PlayerEntryField) is a FormIsland in a plain Wicket form. Its value is converted from JSON and checked by Wicket validators; errors show in the island and in the feedback panel.
  • The high scores (HighScoreList) come from the page-less endpoint scores, which runs without the page lock. Saving a score invalidates scores, so the list fetches them again.

"New game" re-renders the board with Wicket; React keeps the mounted component and updates its props. A new board size replaces the board component, so React mounts a new one.

To change the React components with hot reload, run npm run dev in wicket-examples/src/main/frontend and start the examples in development mode with -Dwicket.islands.devServer=http://localhost:5173.
