1. Request and session scoped beans do not work.
The Web Socket communication is not processed by Servlet Filters and Listeners and thus the Dependency Injection libraries have no chance to export the request and session bean proxies.

2. A connection lasts no longer than the HTTP session it was opened on.
Every message resolves its Wicket `Session` out of that HTTP session, so once the session ends - whether the application invalidated it, a filter or a container-managed logout did, or it simply timed out - the connection is closed with code 1008 and the reason `Session ended`, and no further message reaches the page or the resource. What a callback writes to the session goes to that same HTTP session, so a sign out performed over a connection ends the session of the client as one performed over HTTP does.

3. A connection lasts no longer than the page it was opened for.
Every message looks the page up again in the page store of the session. When the session lives on but the page does not - the store evicted it, or the session survived a restart that the store did not - the connection is closed with code 1008 and the reason `Page expired`, and none of the behaviors of the page is reached, not even `onConnect`. A client can tell the two reasons apart: after `Page expired` reloading the page gives it a working connection again, while reconnecting from the same page does not.
